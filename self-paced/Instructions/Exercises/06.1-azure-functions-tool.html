Exercise 06.1 — Integrate Azure Functions with Foundry agents (queue-based)

Learn how to integrate Azure Functions with Microsoft Foundry agents by using an asynchronous, queue-based architecture. Instead of calling a synchronous HTTP endpoint from client code, the Foundry Agent Service drops tool invocation requests directly onto an Azure Storage queue, your serverless Function processes the request, and the answer is returned through an output queue.

By using this approach, your agents can access enterprise systems and long-running business logic with scale-to-zero pricing, automatic retries, and clean security isolation.

This exercise takes approximately 60 minutes.

Note on Standard Setup: The basic agent setup in Foundry is not supported for Azure Functions queue tools because the tool requires queue resources and network routing that only the standard setup capability host provides.

Task 1: Understand the queue-based tool pattern

In standard function calling (Exercise 06), your client code receives a tool call request from the model, executes the function locally, and submits the result back. In this queue-based pattern, the Foundry Agent Service itself coordinates the entire tool call directly with Azure Storage queues:

StepActionExecuting Component
1. Model DecisionThe user asks a weather question. The model decides to invoke the GetWeather tool with {"location": "Seattle, WA"}.Foundry Model
2. Queue RequestFoundry Agent Service places a message into get-weather-input-queue containing the arguments and an opaque CorrelationId.Foundry Agent Service (Project Identity)
3. Function TriggerThe queue trigger invokes your Function code to process the message and compute the weather.Azure Functions App
4. Queue ResponseThe Function writes the result to get-weather-output-queue, preserving the exact CorrelationId.Azure Functions App
5. Correlation & ResumeThe agent reads the output queue, matches the CorrelationId, and continues the conversation to answer the user.Foundry Agent Service

Task 2: Create the Azure Storage Queues

Create the input and output queues in your Azure Storage account using your Microsoft Entra identity.

  1. Open a PowerShell terminal and set your resource variables:

    $RESOURCE_GROUP = "your-foundry-resource-group"
$STORAGE_ACCOUNT_NAME = "yourstorageaccountname"

  2. Retrieve the primary Queue service endpoint URL:

    $STORAGE_QUEUE_ENDPOINT = az storage account show `
    --resource-group $RESOURCE_GROUP `
    --name $STORAGE_ACCOUNT_NAME `
    --query primaryEndpoints.queue --output tsv

Write-Host "Queue Endpoint: $STORAGE_QUEUE_ENDPOINT"

    Check: The output resembles: https://<storage-account-name>.queue.core.windows.net/.

  3. Create the input and output queues using Entra ID authentication:

    az storage queue create --name "get-weather-input-queue" `
    --account-name $STORAGE_ACCOUNT_NAME --auth-mode login

az storage queue create --name "get-weather-output-queue" `
    --account-name $STORAGE_ACCOUNT_NAME --auth-mode login

    Check: Both queues are created successfully.

Task 3: Configure required RBAC role assignments

To secure access without API keys, two identities need the Storage Queue Data Contributor role on your Storage account:

  1. Assign to the Foundry Project Managed Identity:
    The agent runtime uses the project's system-assigned managed identity to drop messages into the input queue and poll the output queue.

    # Get your Foundry Project Principal ID from the project resource
$PROJECT_RESOURCE_ID = az resource list --resource-group $RESOURCE_GROUP `
    --resource-type "Microsoft.CognitiveServices/accounts/projects" --query "[0].id" -o tsv

$PROJECT_PRINCIPAL_ID = az resource show --ids $PROJECT_RESOURCE_ID `
    --query "identity.principalId" -o tsv

$STORAGE_ACCOUNT_ID = az storage account show --resource-group $RESOURCE_GROUP `
    --name $STORAGE_ACCOUNT_NAME --query "id" -o tsv

az role assignment create `
    --assignee-object-id $PROJECT_PRINCIPAL_ID `
    --assignee-principal-type ServicePrincipal `
    --role "Storage Queue Data Contributor" `
    --scope $STORAGE_ACCOUNT_ID

    Check: Output confirms the role assignment for the project's principal ID.

  2. Assign to your signed-in developer account:
    Required to run the Azure Function locally and interact with the queue using Azure CLI or local Python scripts.

    $MY_USER_ID = az ad signed-in-user show --query "id" -o tsv

az role assignment create `
    --assignee-object-id $MY_USER_ID `
    --assignee-principal-type User `
    --role "Storage Queue Data Contributor" `
    --scope $STORAGE_ACCOUNT_ID

    Note: Azure role assignments can take 1 to 2 minutes to propagate across Microsoft Entra ID.

Task 4: Configure and run the Azure Function

In this task, you run the queue-triggered Azure Function locally using Azure Functions Core Tools. The function listens to the cloud storage queue via identity-based connections.

  1. Navigate to the function_app subdirectory in labs/06.1-azure-functions-tool:

    cd labs/06.1-azure-functions-tool/function_app

  2. Inspect function_app.py:

    import json
import logging
import azure.functions as func

app = func.FunctionApp()

INPUT_QUEUE = "get-weather-input-queue"
OUTPUT_QUEUE = "get-weather-output-queue"

# Queue trigger receives agent tool calls from the input queue
# and returns results through the output queue binding
@app.function_name(name="GetWeather")
@app.queue_trigger(arg_name="msg", queue_name=INPUT_QUEUE, connection="STORAGE_CONNECTION")
@app.queue_output(arg_name="reply", queue_name=OUTPUT_QUEUE, connection="STORAGE_CONNECTION")
def get_weather(msg: func.QueueMessage, reply: func.Out[str]) -> None:
    raw = msg.get_body().decode("utf-8")
    logging.info("Message from agent: %s", raw)

    try:
        messagepayload = json.loads(raw)

        # Extract the function arguments sent by the agent
        function_args = messagepayload.get("function_args") or messagepayload
        location = function_args.get("location", "Unknown location")

        weather_result = f"The weather in {location} is 22 degrees Celsius and sunny."

        # IMPORTANT: Return result with the CorrelationId from the original request!
        response_message = {
            "Value": weather_result,
            "CorrelationId": messagepayload["CorrelationId"],
        }
        reply.set(json.dumps(response_message))
        logging.info("Reply to agent: %s", json.dumps(response_message))

    except Exception as e:
        logging.error("Error processing queue message: %s", e)

    CRITICAL: The response message must include "CorrelationId": messagepayload["CorrelationId"]. The agent service uses this correlation ID to match the function output to the suspended turn. If omitted, the agent will never resume.

  3. Create local.settings.json from the example:

    Copy-Item local.settings.json.example local.settings.json

  4. Edit local.settings.json and replace <your-storage-account> with your actual storage account name:

    {
  "IsEncrypted": false,
  "Values": {
    "AzureWebJobsStorage": "UseDevelopmentStorage=true",
    "FUNCTIONS_WORKER_RUNTIME": "python",
    "STORAGE_CONNECTION__queueServiceUri": "https://yourstorageaccountname.queue.core.windows.net"
  }
}

  5. Start the Function App locally:

    func start

    Check: Output shows the host starting and confirms: Functions: GetWeather: queueTrigger.
    Leave this terminal open and running! It is actively listening to get-weather-input-queue.

Task 5: Define the Azure Function tool and run the agent

Now open a new, second terminal to write and run the agent script.

  1. In the second terminal, navigate to labs/06.1-azure-functions-tool:

    cd labs/06.1-azure-functions-tool

  2. Create and activate a virtual environment, then install requirements:

    py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
pip install "azure-ai-projects>=2.0.0" azure-identity python-dotenv

  3. Create a .env file from .env.example:

    Copy-Item .env.example .env

    Fill in your Foundry project details in .env:

    PROJECT_ENDPOINT=https://your-resource.services.ai.azure.com/api/projects/your-project
STORAGE_QUEUE_ENDPOINT=https://yourstorageaccountname.queue.core.windows.net
MODEL_DEPLOYMENT=gpt-4o-mini

  4. Inspect agent.py:

    import os
from azure.identity import DefaultAzureCredential
from azure.ai.projects import AIProjectClient
from azure.ai.projects.models import (
    AzureFunctionBinding,
    AzureFunctionDefinition,
    AzureFunctionStorageQueue,
    AzureFunctionDefinitionFunction,
    AzureFunctionTool,
    PromptAgentDefinition,
)
from dotenv import load_dotenv

load_dotenv()

PROJECT_ENDPOINT = os.environ["PROJECT_ENDPOINT"]
STORAGE_QUEUE_ENDPOINT = os.environ["STORAGE_QUEUE_ENDPOINT"]
MODEL = os.environ.get("MODEL_DEPLOYMENT", "gpt-4o-mini")

# 1. Create project client
project = AIProjectClient(
    endpoint=PROJECT_ENDPOINT,
    credential=DefaultAzureCredential(),
)
openai = project.get_openai_client()

# 2. Define the Azure Function tool
tool = AzureFunctionTool(
    azure_function=AzureFunctionDefinition(
        input_binding=AzureFunctionBinding(
            storage_queue=AzureFunctionStorageQueue(
                queue_name="get-weather-input-queue",
                queue_service_endpoint=STORAGE_QUEUE_ENDPOINT,
            )
        ),
        output_binding=AzureFunctionBinding(
            storage_queue=AzureFunctionStorageQueue(
                queue_name="get-weather-output-queue",
                queue_service_endpoint=STORAGE_QUEUE_ENDPOINT,
            )
        ),
        function=AzureFunctionDefinitionFunction(
            name="GetWeather",
            description="Get the weather in a location.",
            parameters={
                "type": "object",
                "properties": {
                    "location": {
                        "type": "string",
                        "description": "The location to look up (e.g. Seattle, WA).",
                    }
                },
                "required": ["location"],
            },
        ),
    )
)

# 3. Create a versioned prompt agent
agent = project.agents.create_version(
    agent_name="azure-function-agent-get-weather",
    definition=PromptAgentDefinition(
        model=MODEL,
        instructions="You are a helpful support agent. When asked about the weather, use the GetWeather tool.",
        tools=[tool],
    ),
)
print(f"Agent created (id: {agent.id}, name: {agent.name}, version: {agent.version})")

# 4. Ask a question that triggers the tool
print("\nAsking: What is the weather in Seattle, WA?")
response = openai.responses.create(
    input="What is the weather in Seattle, WA?",
    extra_body={"agent_reference": {"name": agent.name, "type": "agent_reference"}},
)

print(f"\nResponse from agent:\n{response.output_text}")

  5. Run the agent script:

    python agent.py

Knowledge check

1. Why is the standard agent setup required for Azure Functions queue tools?
  • A. Basic setup does not support Python
  • B. Only the standard setup capability host has network and identity routing to access customer-owned Azure Storage queues
  • C. Basic setup does not allow tools

Answer: B

Basic setup uses shared internal Microsoft storage. The capability host in a standard setup connects the agent service to your own Azure resources.

2. What happens if your Function does not return the request's CorrelationId in the output queue?
  • A. The Function crashes with a 500 error
  • B. The agent cannot match the response to the suspended turn and times out waiting for the tool result
  • C. The agent answers without the tool result

Answer: B

The CorrelationId is the only mechanism the agent service has to correlate asynchronous responses with pending requests.

3. Which RBAC role must be granted to the Foundry project managed identity?
  • A. Storage Blob Data Reader
  • B. Storage Queue Data Contributor
  • C. Contributor

Answer: B

The agent service needs `Storage Queue Data Contributor` to write messages to the input queue and poll/read messages from the output queue.
