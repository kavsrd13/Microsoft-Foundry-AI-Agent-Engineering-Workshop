# Client requirements coverage

Every requested topic has a teaching destination. **Build** means runnable source is supplied, not that Azure execution succeeded. **Guided** requires portal, tenant, licence or administrator work. **Decision** produces a reasoned architecture choice. A scaffold is reviewable deployment code, not an already deployed service.

## Additional material and what can be shortened

Original Labs14–15 add framework-specific session providers, middleware denial and redaction. These support engineering understanding but can be optional for a client focused on RAG and deployment. Detailed orchestration alternatives, repeated SDK/framework versions of the same concept, local model setup and a second hosting/channel choice are extension work. Preserve the original files; select a route rather than teaching every variant.

## Integration boundaries

Lab18 uses a small corpus and synthetic `staff`/`hr` permissions. Lab23 uses the original Lab08 corpus and `hr-internal`/`citizen-service` permissions. Lab21 uses verified Entra GUIDs and a dedicated ACL index. These are deliberately separate exercises: no silent schema substitution. Lab18 retrieval reports do not satisfy Lab23 release gates.

The web app does not yet combine Cosmos history, Functions tool dispatch, registered agent versions and full request tracing into one application. That combined product is a capstone extension; the supplied labs teach and exercise its individual mechanics. The infrastructure footprint does not automatically connect BYO Agent Service capability hosts or implement a private production network.
