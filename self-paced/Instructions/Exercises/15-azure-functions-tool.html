Exercise 06.1 — Host an Azure Functions tool (queue-based)

In this exercise, you connect a Microsoft Foundry agent to serverless custom tools hosted on Azure Functions using an asynchronous, queue-based architecture. Instead of calling an HTTP endpoint directly from client code, the Foundry Agent Service drops tool invocation requests onto an Azure Storage queue, your Function processes them with scale-to-zero serverless compute, and the answer is returned over an output queue.

This pattern provides enterprise isolation, automatic retry resilience, and zero-idle-cost execution for long-running workflows.

This exercise takes approximately 120 minutes.

Important: This exercise requires a Standard Setup Foundry project. Basic agent setup is not supported because Azure Functions queue tools require the queue resources and managed network integration provided by the capability host in the standard setup.

Task 1: Understand the queue-based architecture

Before writing code, understand the interaction pattern. Unlike standard in-process function calling where your application loop calls a local function, here the Foundry Agent Service itself orchestrates the entire round-trip directly through Azure Queue Storage:

StepActionExecuting ComponentLocation
1. Tool DecisionThe model decides to call GetWeather with arguments (e.g. {"location": "Seattle"}).Foundry Model InferenceFoundry Service
2. Queue RequestA JSON payload with arguments and an opaque CorrelationId is written to the input queue.Agent Service Runtime (using Project Managed Identity)Azure Storage Queue
3. Function TriggerThe queue trigger fires, running your custom business logic.Azure Functions AppFlex Consumption Plan
4. Queue ResponseThe result is written to the output queue, echoing the exact CorrelationId.Your Function (using Function App Managed Identity)Azure Storage Queue
5. Correlation & ResumeThe agent reads the output queue, matches the CorrelationId, and continues the conversation.Foundry Agent ServiceFoundry Service

Note: Your client application code never talks to the Function or the Storage Queues. Your script simply asks the question and awaits the agent's completed response. The cloud infrastructure handles the asynchronous plumbing.

Task 3: Configure RBAC and resource permissions

Queue-based agent tools require strict, identity-based permissions across multiple Azure resources. If permissions are missing, the agent will hang or return a 403 Forbidden error.

  1. Storage Queue Data Contributor for Foundry Project Managed Identity:
    Allows the agent service to write to the input queue and read results from the output queue.

    $PROJECT_PRINCIPAL_ID = az rest --method GET --url "https://management.azure.com/subscriptions/$SUB/resourceGroups/$RG/providers/Microsoft.CognitiveServices/accounts/$ACCOUNT/projects/$PROJECT?api-version=2025-04-01-preview" --query "identity.principalId" -o tsv

az role assignment create `
  --assignee-object-id $PROJECT_PRINCIPAL_ID `
  --assignee-principal-type ServicePrincipal `
  --role "Storage Queue Data Contributor" `
  --scope "/subscriptions/$SUB/resourceGroups/$RG/providers/Microsoft.Storage/storageAccounts/$FUNCTION_STORAGE"

  2. Storage Queue Data Contributor for Function App Identity:
    Allows the Azure Function to monitor the input queue and post answers to the output queue.

    $FUNCTION_PRINCIPAL_ID = az functionapp identity show -g $RG -n $AZURE_FUNCTION_APP_NAME --query "principalId" -o tsv

az role assignment create `
  --assignee-object-id $FUNCTION_PRINCIPAL_ID `
  --assignee-principal-type ServicePrincipal `
  --role "Storage Queue Data Contributor" `
  --scope "/subscriptions/$SUB/resourceGroups/$RG/providers/Microsoft.Storage/storageAccounts/$FUNCTION_STORAGE"

  3. Storage Queue Data Contributor for Signed-in Developer:
    Required to view, inspect, or test queues using Azure CLI or Azure Storage Explorer.

    $MY_USER_ID = az ad signed-in-user show --query "id" -o tsv

az role assignment create `
  --assignee-object-id $MY_USER_ID `
  --assignee-principal-type User `
  --role "Storage Queue Data Contributor" `
  --scope "/subscriptions/$SUB/resourceGroups/$RG/providers/Microsoft.Storage/storageAccounts/$FUNCTION_STORAGE"

  4. Cosmos DB Data-Plane Role on Database Scope:
    In standard setup, the agent runtime persists agent version definitions into a dedicated container in Cosmos DB. The role grant must be scoped to the entire database (/dbs/enterprise_memory) so dynamically created containers are covered:

    az cosmosdb sql role assignment create -g $RG -a $COSMOS_ACCOUNT `
  --role-definition-id 00000000-0000-0000-0000-000000000002 `
  --principal-id $PROJECT_PRINCIPAL_ID `
  --scope "/dbs/enterprise_memory"

    Check: Run az cosmosdb sql role assignment list -g $RG -a $COSMOS_ACCOUNT to confirm the principal is assigned to /dbs/enterprise_memory.

Task 4: Write the queue-triggered Azure Function

Inspect the implementation in app/function_app.py. Notice how clean the serverless tool is:

import json
import logging
import azure.functions as func

app = func.FunctionApp()

INPUT_QUEUE = "get-weather-input-queue"
OUTPUT_QUEUE = "get-weather-output-queue"

@app.function_name(name="GetWeather")
@app.queue_trigger(arg_name="msg", queue_name=INPUT_QUEUE, connection="STORAGE_CONNECTION")
@app.queue_output(arg_name="reply", queue_name=OUTPUT_QUEUE, connection="STORAGE_CONNECTION")
def get_weather(msg: func.QueueMessage, reply: func.Out[str]) -> None:
    """Answer one tool call from the agent."""
    raw = msg.get_body().decode("utf-8")
    logging.info("Message from agent: %s", raw)

    request = json.loads(raw)

    # The agent puts tool arguments under 'function_args'
    arguments = request.get("function_args") or request
    location = arguments.get("location", "an unknown place")

    # Custom business logic / external API execution
    weather = f"It is {len(location) + 10} degrees and sunny in {location}."

    # CRITICAL: CorrelationId must be echoed back exactly
    answer = {
        "Value": weather,
        "CorrelationId": request["CorrelationId"],
    }

    reply.set(json.dumps(answer))
    logging.info("Reply to agent: %s", json.dumps(answer))

CRITICAL REQUIREMENT: The reply message MUST include "CorrelationId": request["CorrelationId"]. The Foundry Agent Service relies on this identifier to match the response to the suspended tool invocation. If omitted, the agent will never acknowledge the reply and will time out.

Task 6: Describe the tool and create the agent

Now build the agent side. In labs/15-azure-functions-tool, inspect or create ask_the_agent.py.

  1. Define the Azure Function Tool:
    We specify the input queue, output queue, and the function parameter schema using AzureFunctionTool:

    from azure.ai.projects.models import (
    AzureFunctionTool,
    AzureFunctionDefinition,
    AzureFunctionBinding,
    AzureFunctionStorageQueue,
    AzureFunctionDefinitionFunction,
)

def describe_the_tool():
    return AzureFunctionTool(
        azure_function=AzureFunctionDefinition(
            input_binding=AzureFunctionBinding(
                storage_queue=AzureFunctionStorageQueue(
                    queue_name="get-weather-input-queue",
                    queue_service_endpoint=STORAGE_QUEUE_ENDPOINT,
                )
            ),
            output_binding=AzureFunctionBinding(
                storage_queue=AzureFunctionStorageQueue(
                    queue_name="get-weather-output-queue",
                    queue_service_endpoint=STORAGE_QUEUE_ENDPOINT,
                )
            ),
            function=AzureFunctionDefinitionFunction(
                name="GetWeather",
                description="Get the current weather in a location.",
                parameters={
                    "type": "object",
                    "properties": {
                        "location": {
                            "type": "string",
                            "description": "The city or town to look up.",
                        }
                    },
                    "required": ["location"],
                },
            ),
        )
    )

  2. Register the Agent Version:
    Attach the tool definition to a PromptAgentDefinition and publish a version:

    def create_the_agent(project):
    agent = project.agents.create_version(
        agent_name="azure-function-agent-get-weather",
        definition=PromptAgentDefinition(
            model=MODEL,
            instructions=(
                "You are a helpful support agent. When asked about the weather, "
                "always use the GetWeather tool rather than guessing."
            ),
            tools=[describe_the_tool()],
        ),
    )
    print(f"Created agent {agent.name}, version {agent.version}")
    return agent

Knowledge check

1. Why is the standard agent setup mandatory for Azure Functions queue tools?
  • A. Basic setup does not support Python models
  • B. Only the standard setup capability host can bind to customer-owned storage queues and managed virtual networks
  • C. Basic setup does not allow instructions

Answer: B

Basic setup uses shared internal Microsoft storage. The capability host in a standard setup allows the Agent Service runtime to access your own storage queues securely.

2. What happens if the Azure Function does not return the request's CorrelationId in the output queue?
  • A. The function crashes with an unhandled exception
  • B. The agent cannot match the response to the pending tool invocation and times out
  • C. The agent creates a duplicate response

Answer: B

The CorrelationId links the asynchronous answer back to the agent's turn. Omitting it prevents the agent from resuming.

3. Which RBAC role must be assigned to both the Foundry project and Function App identities?
  • A. Storage Blob Data Reader
  • B. Storage Queue Data Contributor
  • C. Cognitive Services Contributor

Answer: B

Both the agent service (to write inputs and read outputs) and the Function app (to read inputs and write outputs) require Storage Queue Data Contributor.
